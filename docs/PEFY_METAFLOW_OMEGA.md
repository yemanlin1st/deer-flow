## 1. Mission

MƐTAFLOW Ω™ is the PEFY-native execution and orchestration layer that turns complex requests into governed, fast, parallel, evidence-aware work across agents, agencies, skills, MCP tools, local runtimes and external providers.

It is intentionally designed **above** any single open-source agent framework. DeerFlow is used as an upstream-compatible execution adapter, not as the owner of PEFY business logic, policy, memory, identity, evidence or IP.

The goal is to improve:

- throughput and task decomposition
- response and production speed
- provider and model flexibility
- parallel execution
- research depth and evidence quality
- agent/agency coordination
- reuse of PEFY skills and prior assets
- human readability and authorial consistency
- security, confidentiality and tenant segregation
- rollback, traceability and controlled continuous improvement

## 2. Why this is not a rename of DeerFlow

DeerFlow is MIT-licensed upstream software. PEFY-GG should preserve its license notices and upstream provenance.

The PEFY differentiator therefore lives in separate control planes:

1. PEA sovereign orchestration
2. five counsellor challenge functions
3. thirteen specialist councils/agencies
4. OMNIA Skillspector security and capability admission
5. MƐTAPEFYON Ω memory, knowledge and evidence fabric
6. PEFY canonical identity, project, event and workflow contracts
7. policy-driven model/runtime routing
8. Deep Loop benchmark and improvement gates
9. humanization and output-hygiene engine
10. brand, IP, confidentiality and release controls

This architecture keeps DeerFlow replaceable and prevents vendor/framework lock-in.

## 3. Operating modes

| Mode | Use | Default execution pattern |
|---|---|---|
| `FLASH` | low-risk, time-sensitive work | one primary agent, minimal retrieval, no unnecessary council fan-out |
| `STANDARD` | normal professional work | primary agent + targeted specialists + verification |
| `PRO` | multi-step deliverables | planning, parallel sub-agents, evidence and quality gates |
| `ULTRA` | complex cross-domain work | multi-agent swarm, memory, tools, sandbox, deep verification |
| `SOVEREIGN` | confidential, regulated, IP-sensitive work | local/private providers preferred, strict data boundaries, PEA/council challenge |
| `WARROOM` | critical incidents and high-stakes decisions | executive control, security/risk/legal challenge, immutable evidence and explicit approvals |

Mode selection is policy-driven. A user may request a mode, but confidentiality, legal, safety or production risk can force a stricter mode.

## 6. Humanization and output hygiene

The final production pipeline contains an explicit `HumanizationGate`.

It removes or corrects artifacts that make professional output read like generic machine-generated copy, including:

- generic chatbot openings and closings
- repetitive formulaic transitions
- inflated promotional language without evidence
- excessive headings, bolding or list scaffolding
- empty conclusions and filler
- repeated synonyms and unnatural rule-of-three phrasing
- generic LLM disclaimers such as “As an AI language model”
- stray generation placeholders
- zero-width characters and invisible formatting artifacts
- accidental model/provider labels in normal client-facing prose
- unnecessary Markdown residue when the destination is not Markdown

The gate **must not** falsify authorship, erase required legal disclosures, remove citations/evidence, or defeat a mandatory provenance requirement. When a contract, regulation, platform or client requires disclosure of AI assistance, that required disclosure is preserved.

The target is not “AI detector evasion”. The target is high-quality human communication, faithful authorship, clean formatting and defensible provenance.

## 7. Memory and context engineering

MƐTAFLOW Ω™ routes memory by tenant, project, sensitivity and purpose.

Recommended PEFY stack:

- OMNIA Core Store for policy enforcement and durable fallback
- structured project vault for project state
- semantic memory backend for approved reusable knowledge
- evidence vault for claims, sources, decisions and approval records
- no cross-client memory leakage
- minimum-necessary context assembly
- progressive skill loading
- context compaction and summary checkpoints

Long-running tasks persist state so interrupted work can resume without silently restarting from zero.

## 8. Model and provider routing

Providers are adapters. PEFY business logic does not live inside a provider prompt.

Routing dimensions:

- capability fit
- latency target
- cost ceiling
- sensitivity / data residency
- context-window requirement
- tool-use quality
- coding / reasoning / multimodal need
- local/offline availability
- benchmark score
- current provider health

Fallback order is policy-controlled and observable.

## 11. Agency behavior

MƐTAFLOW Ω™ may act as a **meta-agency**. It does not try to be the best specialist in every domain. It identifies the mission, activates the right specialist agency, allocates context, assigns acceptance criteria, coordinates parallel work and performs final synthesis and release gating.

Examples:

- video request -> DRAMACLAW Ω STUDIO

- accepted output on first pass
- factual correction rate

Deep Loop promotion requires before/after benchmark evidence.

## 13. Security and autonomy

Default posture:

- deny by default for unknown tools
- least privilege
- sandbox first
- project-scoped credentials
- no secret values in prompts, logs or artifacts
- no account-wide writes without explicit authority
- no destructive tool action without approval and rollback plan
- immutable audit event for high-risk decisions
- per-tenant memory and file boundaries
- signed/promoted capability manifests for production
- production self-mutation disabled by default

Self-improvement is allowed only as:

`discover -> assess -> sandbox -> benchmark -> stage -> approve -> release -> monitor -> rollback`
